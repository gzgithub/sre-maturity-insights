# Code review 修正與驗證

基準：main `47bd1b4`。本分支不包含問卷內容重設；另一個設計 PR 可獨立檢閱。

## 問題與處理

| 問題 | 修正 |
|---|---|
| 首次请求永久 pending，結果頁進不去 | 每次請求 10 秒上限，超時中止客戶端請求；結果照常顯示 |
| 重試耗盡仍顯示背景重試 | 最多四次背景重試，耗盡進入 failed，提供人工重試 |
| 舊重試與 callback 汙染重填答案 | 取消計時器與請求；以 job 身份及問卷 UUID 雙重保護 |
| 保存的答案陣列會受後續修改影響 | 建立聯絡資料、同意與答案的記憶體快照 |
| 回應遺失後重試重複新增 | UUID 作為現有 id 主鍵；ON CONFLICT DO NOTHING，保留首次聯絡資料與同意 |
| attempted 重新整理後永遠放行卻沒有 payload | 還原為 none，保留答案與 UUID，返回聯絡閘門重新提交 |
| 變更團隊／服務仍保留 submitted | 保留答案、撤銷提交標記並換 UUID |
| 還原任意 JSON 混入個資／不合法答案 | zod 白名單、角色與答案驗證；移除未知欄位；儲存異常不阻斷 |
| 延後推薦把相依節點數當鏈長 | 用最長未達成路徑深度，平行前置不相加 |
| 測試依赖「失敗案例必須最後跑」 | 每個案例清理 submission 狀態／timer；共用 fixture，參數化驗證與排序案例 |

## 行為限制

取消客戶端請求不能撤回已抵達伺服器的寫入。冪等 UUID 使原快照重試不會重複，舊 callback 不會放行新問卷。修改答案或情境後視為新的提交。重新整理後不保存姓名／Email，需再次填入；原 UUID 可避免上一個已寫入但回應遺失的提交重複新增。

手動重試只使用本分頁記憶體中的原聯絡資料和原同意；成功、取消或 provider 卸載後釋放。UUID 是去重鍵，不是登入憑證；資料表維持 service-role-only RLS。前端結果仍是設計接受的軟閘門。
